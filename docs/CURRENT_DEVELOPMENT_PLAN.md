# ShotMill 当前开发任务计划

更新于 2026-10-12。本文是**唯一开发任务与状态入口**；旧实现及 P0 的详细记录保留在[验收依据](./ACCEPTANCE_EVIDENCE.md)。

**交付目标：** 保留现有创作界面，项目下可建立多条导演时间线，每条包含多个片段（Task）。采用用户可管理的普通工程文件；本地素材只引用不复制，生成结果写入项目输出目录。ZIP 负责收齐依赖后归档，Windows 应用解压即用，局域网任务按明确状态处理。

## 1. 目标架构与职责

下表描述目标，不能据此宣称已经实现。保持一个客户端和模块化单体后端，不新增架构层级。

| 部分 | 唯一职责与边界 |
| --- | --- |
| 现有界面 · React / Tauri | 保留项目首页与 TerryDirector 编辑体验；工作台显示多条时间线，生成结果用卡片浏览。工程创建／打开、本地文件选择和必要状态操作沿用既有入口。 |
| ProjectGateway / API / Frontend Adapter | 沿用正式调用与界面数据边界；后端更换存储不要求前端理解工程内部结构。 |
| 业务后端 | 管理项目、时间线、任务、提示词、执行快照及结果。提示词增强和视频生成队列独立；增强与审核均可选。 |
| 工程与文件访问 | 普通工程文件是项目内容的唯一保存来源；解析原素材引用、读写工程和生成输出。不为项目建数据库，不保留全局数据库镜像，不强制复制素材入库。 |
| Prompt AI 接入 / 视频生成接入 | 两类 Provider 独立；前者使用用户描述、选中媒体及明确启用的上下文增强提示词，后者提交生成、查询状态和取回结果。Core 不绑定具体模型或厂商。 |
| 客户端外部 | 用户选择的工程文件与原素材；独立保存的应用设置；本机或远端 Prompt AI；局域网 Terry Flow Bridge / ComfyUI 视频执行端。 |

工程文件保存任务、提示词与增强历史、素材引用、执行身份和快照、结果及承接关系。原素材留在原位置，多项目可引用同一文件；删除项目或移除引用不得删除用户原始素材。新生成文件写项目输出目录，历史结果不覆盖。应用设置和密钥独立保存，不进入工程或项目 ZIP。

**保留一处负责文件读写与路径解析、一处负责业务编排。** 工程格式和具体模块划分由开发按简单、清晰的方案选择；不以已有 SQLAlchemy、FileLibrary、数据库导入协议或旧测试预期限制目标架构。

### B0 的两个连续交付

1. **🟢 已完成：真实工程保存／打开。** 用户指定位置创建／打开普通 JSON 工程文件；工程内容完整落盘，SQLAlchemy 仅作为进程内可丢弃的运行索引，应用设置独立。局部验证：无原项目数据库时打开、恢复并继续保存；注入保存失败后原文件及未保存编辑保留；桌面选择器编译与前端入口用例通过。
2. **🟢 已完成：原素材引用与输出落盘。** Tauri 选择本机文件后只登记路径；同盘优先存相对路径，跨盘存绝对路径。预览、可选增强、视频提交和归档通过同一访问层读取；新结果写工程旁的 `.files/outputs/`。局部用例验证两个工程共用原文件而无副本、移除一处引用不删原件、两次生成保留不同结果、归档与重开可读取、原文件缺失有明确错误。转换项目的 16 个素材和 6 个结果已核对可从新目录读取，原始旧目录保留。

每个交付在替换相关路径时同步移除已无用途的旧实现，不长期并行两套项目存储，不另开泛化清理工程。后端允许按职责重构；B0 的前端只做必要入口和数据适配，新增导演视图由 B5 单独实施。

**现有项目处理（用户补充）：** 当前已有项目全部为测试项目，不要求新应用兼容旧数据库或旧工程格式。只保留最近更新的一个测试项目，将其一次性转换为新格式工程；其余旧项目不迁移。实施时记录所选项目名称／ID 和更新时间，使用一次性转换保留该项目内容与所需素材、结果引用，并确认新工程可独立打开；不为此维护旧运行路径、双写、兼容层或通用迁移系统。旧测试数据不约束新架构，转换及验证仍不得误删原始素材；旧数据全面迁移与自动清理不在本轮。

转换证据：仅转换“异星边境 · 电影第一、二场 · 720P”（`project-adfaf0f827d14435a69aa20ba2a58a5a`，更新于 2026-09-22 10:39:57.948068）到 `.shotmill/project-documents/`。工程含 26 个任务、26 条 AI 提示词历史、8 个执行记录、6 个结果、25 条承接关系；22 个素材／结果引用均存在。复制工程到无原数据库的临时目录后已打开并再次保存；旧数据库及原文件未删除。

### B5 的移植范围与两个交付

移植来源为本机干净的 TerryDirector 提交 `109e35ffc059e12005d3107bc8c68bfb90ff13c1`。按用户确认的界面基准接入原时间线、内联提示词编辑和资产池，而非只抽取 Canvas。ShotMill 仅适配工程数据和外层导航；节点通信留在原工具模式。

1. **🟢 已完成：移植导演工作台。** 同一 Task 对应一个片段，直接在 TerryDirector 原时间线内新建、移动、裁长和编辑提示词；资产池属于项目，全局提示词按时间线保存。ShotMill 顶栏承载导入／导出，标题行居中显示总时长；内嵌品牌及保存退出控件已移除。局部证据：前端类型检查、浏览器验证原 Canvas 绘制、内联编辑、新建、重开和导出。
2. **🟢 已完成：编排与工程保存。** 导演编辑自动保存到普通工程文件，失败保留草稿并显示重试；不另建 Clip 真相。单场景浏览器验证拖动、裁长、失败重试与重开；单用例工程文件重开验证起点与时长、执行快照、结果和承接关系。唯一转换的测试工程已补齐新字段，26 个任务在无原数据库环境下可打开。

适配时必须分清三件事：**时间位置、任务故事顺序、生成承接关系。** 原时间线拖动是改变位置，不等于跨片段重排；实际重排才调用已有任务排序能力。改变位置不得暗改 Prompt 或承接来源；片段长度表示下一次生成的计划，不裁剪已有视频，模型时长／帧数限制仍由 Profile 表达。Task 内部 Visual Beat 不变成独立片段。

原节点的“挂起”表示跳过片段，与 ShotMill 的“服务器未响应”不同，状态须按本计划映射；原播放头动画、装饰音频波形和演示进度不能当作真实媒体播放或完成状态。默认不继承固定 24 fps、固定重叠 2 秒等 H3 设置；播放复用已有结果播放器，不扩成多轨剪辑、混音或转场系统。

导演时间线的已有编排与交互优先。原任务列表样式承载多条时间线，结果卡片逐项浏览历史视频；不再提供导演时间线／任务视图切换。

## 3. 已确认的视频任务状态规则

| 情况 | 用户看到的状态与操作 |
| --- | --- |
| 尚未提交给服务器，服务器未响应 | **挂起**，原因“服务器未响应”；保留任务与排队输入，用户可重试提交。 |
| 正在生成，确认服务器退出导致中断 | **失败**，说明服务器退出；已知手动关闭或崩溃时据实显示，无法区分则说明原因未知。用户手动重跑，保留失败历史。 |
| 已经完成并保存结果 | 重新连接后可取回原结果；服务器重启不应要求重新生成。 |
