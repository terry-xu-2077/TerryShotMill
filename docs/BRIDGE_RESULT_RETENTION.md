# Bridge 结果保留与收集边界

适用范围：单用户可信局域网，ShotMill 笔记本客户端与 ComfyUI 台式机服务端。

## 当前保留策略

- 远端完成不是本地完成。ShotMill 下载并校验所有产出、保存文件并成功提交 Result 后，才标记本地任务完成。
- Bridge 不按时间、客户端下载次数或 ShotMill 项目/任务删除自动清理远端结果；本轮没有自动清空功能。
- 上传成功的内容寻址输入、远端结果、任务索引由服务端保留。中断上传仅清理本次临时文件。
- ShotMill 永久删除及独立归档只处理本地拥有的文件，不发送远端删除请求，不删除 ComfyUI 的其他应用产出。
- 没有“下载成功即释放远端文件”的隐式确认。重试下载不改变结果或提交新的生成任务。
- 手工移走或删除远端文件后不能承诺补收；没有本地完整副本前不要清理远端输入、输出或任务索引。
- 当前保留时间无限定，因此需要留意台式机磁盘空间。空间不足应报错，不以自动删除未确认结果腾出空间。

后续如增加服务端清理，必须有明确的任务归属、完整本地保存确认、保留期限与活动输入保护，
不能只凭“没有客户端连接”判断数据无用。该自动清理不属于本轮实现。

## 已验证与待补缺口

已验证：下载中断可重试、摘要错误不发布本地 Result、恢复不重复提交；客户端查询过的
终态会持久化，之后清空 ComfyUI 内存历史仍可按原任务查询。

Bridge 0.5.1 已增加服务端主动完成记录：带 Bridge 归属标记的新任务完成时，
在 worker 返回前将输出与状态原子保存到 `output/shotmill/receipts`，不依赖客户端轮询。
查询会验证原 Job / Prompt 身份并读取该记录。独立包 16 项测试包含无轮询、历史清空、
生产状态函数读取记录、发布失败保留原文件、路径边界和不复制提示词图/额外凭据。
本机实际 PromptQueue 源码的 CPU-only 验证通过，但这不是运行中的服务升级验收。

新任务要求服务端声明 `durableCompletion`；旧任务按原冻结能力恢复，不被新准入要求拦截。
升级前已经入队的任务没有新归属标记，仍采用原来的客户端查询持久化。因此部署前需要
确认队列空闲，并查询、保留旧任务的现有终态，再重启，不能直接假设新机制能补救历史数据。

磁盘写入失败会明确记录错误，保留 ComfyUI 内存历史供查询恢复，不声称已持久化。
在完成钩子原子发布前发生进程强制退出仍可能留下未知结果；不能自动重新提交生成。
该增量已固定在本地独立仓库版本 `5aad93956a3fa52d17b4056b7212e9f76b5e5b87`，并于 2026-09-27 经用户许可部署至本机台式机。实际 ComfyUI 的新任务已验证首次查询前保存 receipt、删除该测试任务的内存历史后仍恢复完成结果，下载摘要一致；不是整个服务再次重启或双机断网验证。

实际 ComfyUI 升级和无模型冒烟已通过，备份位于 ShotMill `.artifacts/bridge-upgrade-20260927`。真实双机断网/休眠恢复、模型视频回归及新版服务再次重启后的补收仍单独验收；本说明不代表这些项目已通过。
