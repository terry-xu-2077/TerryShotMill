# ShotMill UI V0.9 — Batch Review Workflow

> 2026-09-22 产品规则更新：提示词增强和审核均为可选操作，适用于用户界面、Agent、单任务和批量生成。未经增强、未经审核或审核过期不得阻断生成；仅执行校验失败或活动视频任务重复提交可阻断。以下旧版强制审核流程已由此规则覆盖，审核记录及其失效逻辑继续保留。

> 状态：当前 UI 增量规范  
> 最后修订：2026-09-14  
> 关联主任务：`V0.4_BATCH_PRODUCTION_PIPELINE.md`  
> 继承：`UI_V0.8_AI_PROMPT_ENHANCEMENT.md`、`UI_V0.6_PROJECT_CONFIG_H3_EDITOR.md`、`UI_V0.5_PROJECT_WORKSPACE.md`、`UI_V0.5_TASK_EDITOR_REFINEMENT.md`、`UI_DIRECTOR_MODE_GUIDE.md`

本文档定义 V0.4 批量生产能力对应的 UI / UX 增量。

V0.9 不推翻当前“项目首页 → 项目工作台 → 任务编辑弹窗”的信息架构，而是在现有工作台上增加一条更高效的生产路径：

```text
批量 AI 增强
    ↓
集中检查提示词
    ↓
批量视频生成
```

现有单任务编辑、单任务 AI 增强、用户 / AI Prompt 双来源、可视化 / 文本双模式、AI Revision 历史全部保留。

---

# 1. 设计目标

V0.9 优先解决四个真实效率问题：

1. 用户不再需要逐个打开 Task 点击 AI 增强；
2. 批量增强完成后，可以连续检查多个 Task，而不是反复关闭 / 重开编辑器；
3. 用户可以一眼知道哪些 Task 尚未增强、哪些待检查、哪些已经确认；
4. 批量视频生成只处理已经人工确认的 Prompt，不让用户误提交未经检查的任务。

UI 仍坚持：

- 少量高价值信息；
- 不堆工程字段；
- 不用大量彩色 Badge；
- 高饱和色只用于当前动作、警告或失败；
- 列表与卡片是同一 Task 集合的两种视图；
- 右侧详情栏继续只读；
- 真正编辑仍发生在 Task Editor Overlay。

# 2. 工作台主路径

## 2.1 默认状态

项目工作台保持现有结构：

```text
顶部：返回首页 / 项目标题 / 项目配置 / 列表-卡片切换

主区域：Task 列表或 Task 卡片

右侧：只读 Task 详情 / Result 预览

底部：应用设置 + 运行摘要
```

V0.9 不新增“AI 队列”“生成队列”作为一级页面。

## 2.2 创建入口与批量操作入口

任务创建入口统一放在主内容区，不再保留旧的顶部“新建任务 / N 个任务”横向工具栏。

列表模式：

```text
[ 新建任务卡 ]   ← 使用与普通任务行接近的尺寸和视觉语言
[ #1 Task ... ]
[ #2 Task ... ]
```

卡片模式：

```text
[ 新建任务卡 ] [ #1 Task ] [ #2 Task ] ...
```

两种视图都使用同一 `openNewTask` 行为：点击“新建任务卡”后打开现有 Task Editor Overlay，不提前创建数据库 Task。

创建入口需要与真实 Task 有轻微区分，例如虚线边框、加号和辅助说明，但不能重新做成醒目的独立高饱和按钮区域。

批量能力进入 V0.9 后，在工作区提供：

```text
批量 AI 增强
批量生成视频
```

具体位置可在后续 UI 打磨中决定，但不要把批量操作塞入每一张 Task Card，也不要为了批量操作恢复已经移除的旧“新建任务 / N 个任务”工具栏。

当用户多选 Task 时，出现 contextual batch bar：

```text
已选择 12 项
[AI 增强] [标记已检查] [生成视频] [取消选择]
```

“标记已检查”只能用于当前有效 Prompt 已存在且合法的任务；如果设计实现后认为容易误操作，可以只保留在 Task Editor 中逐项确认，第一版不强制提供批量确认。

默认推荐：**不提供一键全部审核通过**。审核本身应该保留人工逐项检查价值。

# 3. Task 状态呈现

## 3.1 用户真正需要看的状态

Task Card / Table 不直接展示 Domain enum，而用简洁中文表达：

```text
AI 未增强
增强中…
待检查
已检查
生成中 62%
已生成
失败
```

不要同时显示五六个 Badge。

推荐将状态拆成两个轻量区域：

```text
提示词：待检查
视频：未生成
```

或在更紧凑的卡片中只显示当前最需要行动的状态：

```text
待检查
```

具体视觉可以继续迭代，但信息优先级必须稳定。

## 3.2 状态优先级

当多个后台状态同时存在时，Task 的主要状态优先显示最需要用户注意的动作：

```text
失败
> 增强中 / 生成中
> 待检查
> 已检查
> 已生成 / 空闲
```

但视频已有 Result 不应掩盖“当前 Prompt 又被重新增强、需要重新检查”的事实。

## 3.3 颜色

- 正常文本和大多数状态使用低饱和中性色；
- `待检查` 可使用轻微强调，不需要大面积黄底；
- `生成中 / 增强中` 使用当前产品主强调色；
- `失败` 才使用明确错误色；
- `已检查 / 已生成` 不需要鲜绿色大块强调。

# 4. 批量 AI 增强

## 4.1 点击行为

用户点击“批量 AI 增强”后，打开轻量确认 Overlay / Dialog。

内容只展示用户做决定真正需要的信息：

```text
批量 AI 增强

将处理 18 个任务
AI：Qwen3.8

项目背景        [✓]
上一任务摘要    [✓]

执行顺序：按当前任务顺序

[取消]    [开始增强]
```

如果某些任务已有 active Prompt Job：

```text
18 个任务中：
15 个将加入队列
3 个正在增强，将跳过
```

不要让用户看到 Provider endpoint、模型文件路径、Context Snapshot ID 等工程字段。

## 4.2 未选择 Task 时

如果点击工作台全局“批量 AI 增强”，默认目标为当前项目中**可增强的全部 Task**。

如果已有多选，则只处理当前选中 Task。

确认窗口必须显示实际将处理数量。

## 4.3 提交后

用户确认后立即关闭确认窗，不需要阻塞工作台。

底部运行摘要开始显示：

```text
AI 提示词    3 / 18
当前：任务 04 · 仓库入口
```

Task Card / Table 随 SSE 更新状态。

用户仍然可以继续查看项目、编辑其他尚未进入 active job 的 Task，或检查已经完成的任务。

# 5. 批量运行中心

## 5.1 底部运行摘要

当前项目底部右侧从单一运行摘要升级为双工作流摘要：

```text
AI 提示词     7 / 20
视频生成      2 / 12
```

有 active job 时可以增加当前项：

```text
AI 提示词     7 / 20
当前：任务 08 · 进入仓库

视频生成      2 / 12 · 62%
当前：任务 03 · 雨夜码头
```

但默认底栏保持紧凑，不常驻展开完整 Job 列表。

## 5.2 查看全部

点击运行摘要或“查看全部”打开轻量运行中心 Overlay / Drawer。

建议结构：

```text
运行中心

AI 提示词
────────────────
任务 08   增强中…
任务 09   排队
任务 10   排队
任务 05   失败      [重试]

视频生成
────────────────
任务 03   62%
任务 04   排队
```

第一版不需要做复杂 Render Manager。

必须支持：

- 看清当前项；
- 看清排队项；
- 看清失败项；
- 重试失败；
- 停止后续排队；
- 不显示大量内部 Job ID。

# 6. Task Editor 连续审核模式

这是 V0.9 最重要的 UI 效率改进。

## 6.1 顶部任务导航

Task Editor 顶部增加：

```text
‹ 上一个任务        07 / 24        下一个任务 ›
```

导航顺序以当前工作台 Task Order 为准。

如果用户是在筛选结果或某个选中集合中进入编辑器，第一版仍建议按项目稳定 Task Order 导航，避免导航语义随临时筛选发生不可预期变化。

## 6.2 保留现有 Prompt Source

提示词区域继续：

```text
[用户提示词] [AI 增强提示词]

[可视化] [文本]

Prompt 编辑区域
```

规则继续成立：

- 当前选中的 Source 决定真正使用哪份 Prompt；
- 可视化 / 文本只改变同一份 Prompt 的编辑呈现；
- AI Tab 保留 Revision 历史；
- 单任务“增强”按钮继续存在；
- AI Tab 没有结果时继续显示明确空状态。

## 6.3 底部主动作

审核场景下，底部建议：

```text
取消       上一个       确认并下一个       保存
```

具体顺序可继续视觉调整，但 `确认并下一个` 应成为批量审核时的主动作。

更推荐的逻辑是：

```text
确认并下一个
= 保存当前修改
+ 后端确认当前有效 Prompt
+ 成功后打开下一个 Task
```

如果保存 / 确认失败，不跳转。

## 6.4 已检查状态

在底部保存按钮左侧、Prompt Source 状态附近或标题区，用简洁文字显示：

```text
待检查
```

确认后：

```text
✓ 已检查
```

如果用户随后修改当前有效 Prompt，应立刻回到：

```text
待检查
```

不要通过弹窗打断用户，只更新状态。

## 6.5 已使用哪份 Prompt

继续遵守当前决策：

当 AI Tab 是当前 Source：

```text
已使用 AI 增强提示词
```

当 User Tab 是当前 Source：

```text
已使用用户提示词
```

该提示仍位于底部操作区靠近按钮的位置，不恢复旧“采用增强结果”按钮。

# 7. 审核节奏

推荐用户可以完成如下连续动作：

```text
打开第 1 个待检查 Task
↓
看 AI Prompt
↓
确认并下一个
↓
第 2 个
↓
修改两句
↓
确认并下一个
↓
第 3 个
...
```

因此编辑器切换下一 Task 时需要：

- 保持 Overlay 不关闭；
- 尽量保持编辑器整体布局稳定；
- Prompt 内容区域更新；
- Task 标题 / assets / 参数同步更新；
- 不产生明显页面闪烁；
- 当前 Task 有未保存修改时，直接点击“下一个”必须保护用户数据。

推荐：

- `确认并下一个`：保存 + 确认 + 跳转；
- 纯“下一个”：如果有未保存修改，先提示保存 / 放弃；
- 无修改则直接跳转。

# 8. 批量视频生成

## 8.1 点击入口

全局或多选 contextual bar 中点击“批量生成视频”。

弹出轻量确认窗：

```text
批量生成视频

已选择 24 个任务
18 个可生成
4 个待检查
1 个正在生成
1 个参数无效

将提交 18 个任务

[取消]    [开始生成]
```

用户不需要了解 eligibility 的内部规则，只需要看到为什么有任务没有进入队列。

## 8.2 不允许静默生成未审核任务

默认必须明确：

```text
未检查的任务不会生成
```

V0.9 不提供“忽略审核直接全部生成”的显眼快捷按钮。

如果未来增加高级覆盖，也应藏在高级设置，而不是默认主路径。

## 8.3 提交后

视频 Job 进入现有 Generation Queue。

底部运行摘要显示：

```text
视频生成    1 / 18 · 42%
```

已有 Result 的 Task 重新生成后，旧 Result 保留；UI 默认展示新的 Primary Result 规则继续沿用 V0.3。

# 9. 列表模式

Table 每行建议只增加必要状态列，不扩张成数据管理后台。

推荐列信息：

```text
序号
任务名
提示词
视频
时长
结果
```

其中：

```text
提示词：未增强 / 增强中 / 待检查 / 已检查
视频：未生成 / 排队 / 62% / 已生成 / 失败
```

不要增加：

```text
PromptJobId
BatchId
RevisionHash
ProviderProfile
ContextSnapshot
```

这些不属于默认产品 UI。

# 10. 卡片模式

Task Card 继续优先展示：

- 代表帧 / Result；
- Task 标题；
- 关键状态；
- 时长等必要信息。

V0.9 可以在卡片底部增加非常轻量的生产状态，例如：

```text
提示词 · 待检查
视频 · 未生成
```

或更紧凑地仅突出当前动作：

```text
待检查
```

卡片不增加 AI 增强 / 生成按钮矩阵。

右键菜单可保留：

```text
编辑任务
AI 增强
生成视频
```

但批量能力主要入口仍在工作台批量操作区 / contextual bar。

---

# 11. 多选交互

列表与卡片都应共享同一选中集合。

至少支持：

- 单击选择；
- Ctrl / Cmd 多选；
- Shift 连选；
- Esc 清除多选；
- 切换列表 / 卡片模式后保留选中集合。

批量操作以后仍保留或清除选择，可以按动作决定：

- 提交批量 AI 增强后建议保留选择，便于用户继续观察；
- 批量视频生成后也可以保留选择；
- 用户显式点击“取消选择”才清空。

# 12. 空状态 / 部分失败

## 12.1 没有可增强 Task

显示：

```text
没有可加入 AI 增强队列的任务
```

并简短解释，例如：

```text
选中的任务正在增强，或缺少必要的提示词内容。
```

## 12.2 部分失败

Batch 完成后不要用全屏错误提示。

底部运行中心显示：

```text
AI 提示词 · 已完成，2 项失败
```

点击后看到失败任务与简短原因，可选择：

```text
重试失败任务
```

## 12.3 Provider 不可用

如果 Qwen3.8 Runtime 未启动 / Provider 不可用：

- 立即停止新的 batch 提交；
- 显示明确中文错误；
- 已存在 queued 项保持可恢复状态或按后端策略失败；
- 不伪造 AI 结果。

# 13. 视觉打磨重点

V0.9 继续打磨 UI，但不做整体信息架构翻新。

本轮重点：

## 13.1 创建入口与批量操作层级

- 列表与卡片模式统一使用主内容区“新建任务卡”；
- 新建入口视觉上接近普通 Task，但通过虚线、加号和辅助文字明确其创建语义；
- 不恢复旧顶部“新建任务 / N 个任务”工具栏；
- “批量 AI 增强 / 批量生成视频”要明显但不抢夺项目标题视觉中心；
- 多选后 contextual bar 的出现要稳定，不使主内容整体跳动。

## 13.2 Task 状态密度

- 不要四五个不同色 Badge；
- 卡片和表格使用相同语义；
- 正常状态尽量中性；
- 只突出“用户现在应该做什么”。

## 13.3 Task Editor

- 上一个 / 下一个导航视觉上归属于任务标题区；
- Prompt 编辑区仍然是绝对主视觉；
- `确认并下一个` 是批量审核时主按钮；
- “已使用 AI 增强提示词 / 用户提示词”仍紧邻底部按钮，不移回 Prompt 内容内部；
- AI Revision 历史不要挤占编辑区高度。

## 13.4 运行中心

- 默认折叠；
- 只在用户需要时展开；
- AI / Video 两类任务视觉区分清楚；
- 不做 ComfyUI Queue 的复制品。

# 14. 手机端

V0.9 的桌面批量审核是主目标。

手机端这一版至少保持：

- 项目工作台可打开；
- 可查看 AI Prompt Queue / Video Queue 进度；
- 可看到失败项；
- 不产生页面级横向溢出。

手机端不要求在 V0.9 完整承担 Prompt 长文本编辑与批量审核。

完整远程进度页继续作为后续专项。

# 17. V0.9 后续打磨

完成首轮批量链路后，再根据真实使用反馈继续调整：

- Batch bar 位置；
- 状态文字密度；
- 卡片模式是否只显示最高优先级状态；
- 审核导航是否需要“只浏览待检查”；
- 运行中心是否需要暂停 / 恢复；
