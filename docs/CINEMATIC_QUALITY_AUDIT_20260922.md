## 已确认的问题

### 1. 不只是提示词格式变化，生成配置也变了

从视频内实际执行图追踪开关的生效分支，不能仅凭节点列表判断：

|---|---|---|
| 底模 | minimax_h3_fl2va_pruned_int8_convrot | Minimax-h3_Singularity_ref2va_v1.3_int8 |
| 加速LoRA | fl2v_turbo_8step_v1.0，strength=1 | ref2v_turbo_4step_v0.1，strength=1 |
| 步数/调度/采样器 | 8 / beta / euler | 8 / beta / euler |
| 模型附加处理 | Spectrum + video sigma shift 6 / audio 3 | 未经过旧Spectrum与sigma shift分支 |
| 参考图处理 | max | max |
| 编码器 | qwen3vl_32b_minimax_h3_int8_convrot | 同左 |

旧样本不是统一配置：CUT_01_00012 使用simple调度和TurboSampler，Easy样本又有不同设置。因此不能笼统地说旧片与新片唯一差别是H3格式，不能未经对照就认定Singularity一定更差。4step文件名配8步也不是单凭名称即可判定的错误，但值得单独验证。

提示词增强使用的Qwen与视频模型内的Qwen文本/视觉编码器不是同一层；不能混为“换掉Qwen就解决”。

### 2. 制作输入削弱了摄影设计

本次create-tasks.py统一附加“每个片段最多两个清楚衔接的镜头”、冷灰紫基调、禁止新增音乐；47项多为8–12秒，全部contextMode=不承接，上一任务摘要也未启用。覆盖剧情对白不等于保留电影节奏。这里有本次任务规划与人工审核的责任，不能全部归咎于增强模型。

旧提示词按手部特写、人物反应、巨构全景组织情绪变化，逐镜明确景别、构图、光源、运镜动机和声音远近。旧文件Easy_00006仅5.875秒，也具有明显的尺度关系和侧逆光，证明“不是15秒”不是唯一病因。

新S01-02反复强调匀速、幅度小、动作极小、稳定收尾；新S01-01在同一近景里放入操纵杆、缠胶带、能量匣、人物对白、车外轮腿等多重信息，缺少有效的注意力分配。新生成整体偏均匀灰紫，旧片更强调主体边缘光、深色负补光与暖冷分离。

### 3. 格式合规没有等于导演质量合格

六段H3输出花了大量文字复述身份和“fully_preserved”，并不证明画面已保留参考。Qwen已发生外观/物件误读，但是否由模型能力、输入组织或系统提示导致，需要单独对照；不能把“专用格式”当质量保证，也不能先验禁止这种格式。

### 4. 物理与空间连续性不能仅靠笼统身份约束

用户指出S01-02人物坐车尾驾驶；实际文本写驾驶舱内，但没有稳定描述驾驶座/操纵装置/货斗的空间关系。新14抽帧出现车辆向缝隙下方运动的画面，需要检查原意“越过裂缝”是否在动作全程实现，而不仅看车与人物有没有出现。旧样本也含六条机械足等不准确描述，不能机械照搬全部文字。

## 修正原则

- 先编排完整戏剧单元，再选择适合一次生成的多镜头组合；正式生产优先接近15秒，必要时允许更短，不为凑时长硬塞动作。
- 先保留导演意图（观看对象、景别变化、镜头动机、光源方向、情绪节奏），再适配格式。格式转换不能自动把动态设计改成匀速、微动、静态展示。
- 参考素材定义保持简洁且准确；同一物件在各段不能自相矛盾。空间约束用正向可见关系表达。
- 区分单任务内部连续性与跨任务承接；相关任务显式设计尾帧/片段承接或连续性说明，不宣称一个选项能保证衔接完美。
- 审核要看剧情结果和镜头表现，不能以能解码、脸像、字段齐全代替通过。
- 工作流质量基线须固定并可追踪；模型/LoRA/shift/采样器变化后先用基准镜头复验。
